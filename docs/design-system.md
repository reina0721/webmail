# Mail Web 客户端设计规范

本次工作区的布局、DOM 与操作生命周期来自固定 Bulwark 基线；粉白配色、轻边界、低对比层级及动效参考 kirakira.moe。保留 Mail Web 名称，不使用参考站点的标识或素材。旧平台的邮件行、阅读卡片、运营页面、HeroUI 和旧全局样式不参与装配。

## 组件与样式边界

- `frontend/packages/material-ui` 是 MUI 二次封装的唯一入口。基础控件、焦点、浮层、色板、密度和减少动态效果由该包管理，业务层不直接导入 MUI。
- 导入的 `src/components/ui` 保持 Bulwark 业务接口，按钮、输入、对话框与菜单底座转接该包。邮件行、线程、附件、文件夹、编辑器和模块工作区继续使用完整的上游业务组件。
- 新入口只加载导入客户端的 `bulwark-globals.css` 和独立 `@mail-web/ui/client.css`。MUI 使用 CSS layer；顺序为 theme、base、mui、components、utilities。浮层共用同一个主题，禁止通过全局高优先级覆盖控件内部样式。
- 旧设计文档已标明历史属性，不作为本次验收。来源、适配与文件哈希见 `docs/upstream/`。

## 视觉与密度

| 用途 | 浅色 | 深色 |
| --- | --- | --- |
| 主色 | `#e36389` | `#f3a5c1` |
| 文字 | `#343034` | `#f3e7ef` |
| 模块侧栏 | `#fff9fb` | `#251e2a` |
| 选中背景 | `#fbe8f1` | `#463040` |
| 细边界 | `#eee1e9` | `#433447` |

控制台与安装表单采用相邻的 Material 色板，所有颜色由主题和令牌管理。普通卡片依靠留白与细边界分组；浮层使用轻阴影。按钮不使用默认大面积 Material 阴影。图标按钮桌面保留紧凑密度，触控命中区至少 44px；选中项同时使用边界、字重或图标状态，不只依赖颜色。

## 工作区与交互

桌面保留窄应用栏、模块侧栏和主工作区。邮件默认文件夹、列表、阅读三栏，提供完整列表、底部阅读、分隔条调整、全屏和独立邮件页面。设置保留上游完整分类；管理员只有 `/console/` 一个入口，个人身份、签名与阅读偏好仍在个人设置。

移动端使用单列与抽屉，阅读、写信和列表之间有明确返回关系。切换账号后保持各自状态与缓存，所有请求仍由 Rust 验证账号。右键、悬停、批量操作、草稿恢复与可撤销操作保留上游生命周期。关闭未保存配置必须提供继续编辑和放弃选项。

原生写信弹窗使用上游 `PopoutShell` 的封装会话交接，主窗口持有实时事件与全局提示；子窗口不重复初始化整套工作区。普通阅读与附件预览使用各自受保护的传输，HTML 隔离在阅读 iframe。

## 动效与可访问性

内容进入使用 180ms、5px 位移；对话框进入使用 140ms、8px 位移和轻微缩放。按压反馈限于 1px 位移。减少动态效果时取消动画、过渡与按压位移。按钮、分栏、菜单和对话框保留键盘与焦点返回语义；全局提供跳到内容和状态播报。

## 证据

浏览器和真实服务逐项结果见 `feature-parity.md` 与 `rebuild-test-report.md`。本规范不代替五种宽度、所有浮层与完整功能的验收；未验证的场景保持待完成状态。
